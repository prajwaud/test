# Prompt changelog

One entry per change to `system.md`. Record the reason, not just the diff - git already has
the diff. In six months the reason is the only part you will not be able to reconstruct.

Format:

```
## v<n> - YYYY-MM-DD
**Changed:** what
**Because:** what the previous version got wrong, ideally with the specific brief that
showed it
**Result:** did it work
```

---

## v1 - 2026-08-13

**Changed:** Initial version.

**Because:** Nothing to compare against yet. The triage taxonomy (ACTION REQUIRED /
NEEDS A REPLY / FYI), the demotion rule for vendor outreach, and the 400-word cap are all
first guesses derived from one hand-assembled brief, not from observed preference.

**Result:** Unknown. Untested against real reactions.

**Open questions this version does not answer:**
- Is 400 words right, or is it too long to read at 5am?
- Should ACTION REQUIRED include things due this week, or only today?
- Should the brief mention meetings that were cancelled, or is that noise?
- Does grouping by urgency beat grouping by sender or by workstream?
